# Digital Access Now — Volunteer Page Redesign Brief

**Page:** `/volunteer`  
**Scope:** Volunteer page only  
**Framework:** Existing Next.js website  
**Primary goal:** Reposition the volunteer page from a list of internal roles into a clear, mission-driven pathway for people to contribute to DAN's work.

---

## 1. Design Direction

The page should feel:

- Human, credible, and mission-driven
- Youthful but not playful
- Modern without looking like a generic AI-generated nonprofit template
- Clear, spacious, and easy to scan
- Focused on action, contribution, and real-world impact

Avoid:

- Excessive gradients
- Generic technology graphics
- Glowing globes, holograms, circuit imagery, or AI-style decorative visuals
- Too many cards with identical styling
- Overuse of icons
- Large blocks of centered text
- Stock-photo-heavy layouts

Use real DAN program or volunteer photography whenever available.

---

## 2. Volunteer Page Color Palette

Use this palette only for the volunteer page redesign unless later adopted sitewide.

| Role | Color | Hex |
|---|---|---|
| Primary | Deep Teal | `#0F5D5E` |
| Secondary Accent | Sky Blue | `#4DB7E5` |
| Mid Teal | Medium Teal | `#238C91` |
| Light Accent Background | Pale Sky | `#EAF7FC` |
| Main Background | Warm White | `#FAFAF7` |
| Primary Text | Charcoal | `#1F2933` |
| Border / Neutral | Soft Gray | `#E7ECEF` |
| White | White | `#FFFFFF` |

### Color Usage Rules

- Use **Deep Teal** for primary buttons, important headings, key icons, and strong visual anchors.
- Use **Sky Blue** only as a secondary accent for links, small highlights, labels, or decorative details.
- Use **Warm White** or white for most page backgrounds.
- Use **Pale Sky** for selected content sections, callouts, or subtle background separation.
- Use **Charcoal** for body text instead of pure black.
- Do not use teal and sky blue at equal visual weight.

### Access → Skills → Opportunity Colors

Use the progression consistently:

- **Access:** `#4DB7E5`
- **Skills:** `#238C91`
- **Opportunity:** `#0F5D5E`

## 7. What Volunteering Can Look Like

### Heading

`What volunteering with DAN can look like`

Use a lighter visual treatment than the contribution cards.

Display six actions:

- **Teach** — Co-facilitate an AI or digital-skills workshop.
- **Mentor** — Guide a student through a project or learning goal.
- **Build** — Help create technology, curriculum, resources, or program infrastructure.
- **Organize** — Support a community event, chapter initiative, or device drive.
- **Connect** — Help participants discover education, leadership, and career opportunities.
- **Lead** — Take responsibility for a project or help train future volunteers.

Suggested layout:

- Desktop: 3 x 2 grid or horizontal editorial layout
- Mobile: stacked list

Do not over-box this section.

## 16. Typography & Layout Guidance

Keep the site's existing type family unless there is a strong reason to change it.

Recommended hierarchy:

- Hero heading: large, bold, left aligned
- Section headings: medium-large, concise
- Body copy: readable line length, approximately 60–75 characters
- Avoid excessive uppercase beyond small eyebrow labels
- Avoid all-centered sections throughout the page

Spacing:

- Use generous vertical spacing between major sections
- Keep internal card padding consistent
- Use whitespace to create hierarchy instead of adding more borders or shadows

## 18. Responsive Behavior

### Desktop

- Hero: 2-column
- Access/Skills/Opportunity: horizontal flow
- Contribution areas: 3-column x 2-row grid
- Volunteer actions: 3-column x 2-row or editorial grid
- Process: horizontal or connected stepped flow

### Tablet

- Hero may remain 2-column if readable
- Contribution cards: 2 columns
- Process: 2-column or wrapped flow

### Mobile

- Single-column layout
- Keep primary CTA visible early
- Stack Access → Skills → Opportunity vertically
- Contribution cards: one per row
- Process: vertical timeline
- Avoid horizontal scrolling

---

## 19. Accessibility Requirements

- Meet WCAG AA color contrast standards.
- Do not use color alone to communicate Access, Skills, and Opportunity.
- All images require descriptive alt text.
- All interactive elements must have visible keyboard focus states.
- Accordion FAQ must be keyboard accessible and use appropriate ARIA attributes.
- Buttons should have clear descriptive labels.
- Maintain minimum touch target sizes on mobile.

---

## 20. Content / Product Requirements

- Use one primary volunteer application destination across the page.
- Do not duplicate “Apply Now” on every contribution card.
- Do not display unverified impact or volunteer counts.
- Keep volunteering broader than internal professional roles.
- Preserve specialized roles such as web development, fundraising, social media, and grant writing under the broader contribution categories.
- The page should communicate mission first, then options, then application.

---

## 22. Definition of Done

The page is ready when:

- The hero has updated messaging and one primary CTA.
- Unverified volunteer-count language is removed.
- Access → Skills → Opportunity is clearly visible.
- Existing four-role job-board presentation is replaced with broader contribution areas.
- Volunteer process is clear.
- Remote/local flexibility is accurately represented.
- FAQ is volunteer-specific.
- Application CTA is consistent across the page.
- Teal/sky-blue palette is implemented consistently.
- Page is responsive and accessible.
- Real DAN photography is used where available.
- Page does not introduce unrelated organization content.
